# docs/PRODUCT.md — 产品要求

> 本文是产品需求的权威来源。需求变更先修改本文并登记 `docs/DECISIONS.md`，再进入任务。此前确认的需求全部收拢在项目文档内，不依赖任何聊天记录。

## 1. 定位与节奏

- Windows 个人晚间复盘助手，单用户本地应用。
- 每天用 3—5 分钟完成一次复盘：结合《纳瓦尔宝典》理解当天的取舍，通过最小实验验证改进建议，并自动沉淀到 Obsidian。
- 目标是判断清晰与低负担，不是打卡与效率考核。

## 2. 晚间复盘流程

默认流程：**自由讲述 → 最多两个单问题追问 → 简短反馈 → 可选行动 → 结束 → 自动沉淀**。

- 追问最多两个，均为单问题；更深入的对话必须由用户主动选择。
- 默认反馈约 250—450 个汉字；详细解释与原文出处默认折叠，点开才显示。
- 随时可跳过追问或结束；结束不要求完成任何"作业"。
- 输入方式：键盘输入、剪贴板粘贴、Windows `Win+H` 听写。
- 提供"今天只记一句"的简短模式：只记录一句话与情绪标记，不触发模型反馈。
- 漏记后直接继续当天，不要求补写历史，不使用打卡清零等惩罚机制。
- 肯定必须对应用户自述的实际行为，不做无依据的夸奖。
- 输出必须区分：用户自述、用户明确感受、AI 假设（须标注）、原作者观点（须标注出处）、情境化建议。
- 点击"结束"不代表接受建议；仅当用户明确同意后才登记为行动。
- 用户输入先落库，再发起模型请求，任何网络故障不丢失已讲内容。

## 3. 价值判断边界

- 不设置"人生效率分"、"纳瓦尔合格率"等量化评分。
- 修耳机省钱、科研推进、休息和人际交往不能只凭"理想时薪"判断价值；应结合预算、替代活动、精力与长期影响综合看待。
- 涉及投资话题：只检查判断过程与原则适用条件，不提供交易执行、不接入实时行情。

## 4. 思想库

- 首批原则来自《纳瓦尔宝典》公开英文版（navalmanack.com，见 `docs/REFERENCES.md` R-1），覆盖：时间取舍、专长、长期关系、判断产出。
- 原则卡字段：英文短摘录、章节链接、来源快照、定位（如财富/幸福）、中文解释、适用边界。
- 引用纪律：原文引用必须与来源快照匹配；中文归纳一律标记为"解读"，不得冒充原文。
- 新增入口：摘录粘贴、Markdown 文件、TXT 文件、个人建议。生成原则卡后须经用户确认才启用。
- 不同来源冲突时，分别说明各自的条件与边界，不强行统一。

## 5. 最小实验

固定流程：

1. 提出三个可能影响结论的假设；
2. 选择最关键的一个；
3. 明确动作、投入、周期、观察指标、继续条件与停止条件；
4. 给出明天就能开始的第一步；
5. 根据实际结果调整判断。

约束：默认周期不超过七天；同时最多一个进行中的实验；不要求每天创建实验。

## 6. Obsidian 与报告

- 默认库位置：`<你的用户目录>\Documents\Obsidian Vault\个人成长\晚间复盘`（可在设置修改；默认从当前用户主目录推导）。
- 目录分类：日报、周报、月报、年报、原则、实验。
- 日报内容：当天经历、明确感受、值得保留的做法、待验证解释、相关思想（含出处）、已选行动。原始对话保留在应用内，不写入笔记。
- 生成时机：日报在结束复盘时生成；周报覆盖周一至周日；月报、年报按自然周期；周期结束后在应用运行且预算允许时生成；空周期不生成。
- 诚实性：报告注明实际记录覆盖范围，不编造缺失日期或趋势；结论保留原始日报的证据索引，不把层层摘要当作事实。

## 7. 界面与状态

界面规范见 `docs/UI_SPEC.md`。状态区分是产品要求的一部分：对话必须区分已保存、提炼中、提炼失败、已导出、导出失败，不允许用一个"成功"掩盖不同环节。

## 8. 七天试用目标

至少五次短复盘；一个实验获得可解释反馈；观察判断清晰度与使用负担。试用结论不得宣称"习惯已经养成"。

## 9. 明确不做

- 不做效率评分与打卡惩罚；
- 不做补作业机制；
- 不接入交易执行或实时行情；
- 不自动把"也许可以"变成已接受行动；
- 不编造记录、趋势或引文。
