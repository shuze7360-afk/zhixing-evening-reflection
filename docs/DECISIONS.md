## D-014 渲染进程安全基线与预加载打包（2026-10-01，ER-001）

- 窗口开启 `contextIsolation: true`、`sandbox: true`、`nodeIntegration: false`（严于 `ARCHITECTURE.md` §2 的最低要求）；
- sandbox 模式的预加载脚本不能 `require` 相对模块，因此 preload 由 esbuild 打包为单文件（`scripts/build-preload.mjs`）；`src/shared/ipc.ts` 是 IPC 通道白名单的唯一登记处，主进程只注册白名单通道，preload 只暴露白名单 API；
- 窗口拒绝 `window.open` 与白名单外导航；生产模式（file:// 加载）由主进程注入 CSP 响应头，开发模式仅监听本地 Vite 服务。

## D-015 SQLite 引擎采用 node:sqlite 内置模块（2026-10-01，ER-002）

- 实测：Electron 44.5.1 内置 Node 24.21.0 提供 `node:sqlite`（`DatabaseSync`，经 `ELECTRON_RUN_AS_NODE` 验证可用）；
- 相比 better-sqlite3：零原生模块，消除 Electron ABI 重编译、prebuild 下载与打包链路风险（本机 GitHub 直连不稳，原生模块链路脆弱）；
- `ARCHITECTURE.md` §1 已同步修订。ER-002 起数据库一律使用 `node:sqlite`。

## D-018 审阅绑定的活性语义（2026-10-01，ER-003 轮；源自 ER-000 审阅预告的"候选核对语义改进"）

- **问题**：候选按目录枚举核对时，后续任务对 `src/` 等共享区域的任何改动都会使全部历史候选哈希失配，迫使每轮重审所有历史任务——"候选踏轮"使流水线不可持续，也违背"受影响的审阅结论失效"中"受影响的"这一限定。
- **语义**：
  - **活动任务**：候选哈希必须与当前内容一致、审阅必须绑定当前候选哈希——硬性校验（"历史审阅冒充当前通过"在此拦截）；
  - **历史任务**：候选被后续任务演进时，绑定转为**存档标注**（检查输出注明"增量由后续任务审阅覆盖"），不再硬性失败；候选清单记录本身（文件存在、hash 内部一致、候选文件未删除）始终硬性校验；
  - 每个任务的交付完整性由"其审阅时点的候选 + 后续任务对增量的审阅"链式覆盖；最终由 ER-005 的整树审阅收口。
- 负反例验证随语义更新重跑（见 `tasks/ER-000/evidence/07-checker-semantics-v2.txt`）：活动任务篡改仍被拦截。

- 与常驻应用并发：SQLite WAL + busy_timeout；数据库路径自动探测（打包版/开发态），`ZHIXING_DB_PATH` 供显式指定；`ZHIXING_OBSIDIAN_DIR` 为**进程内**导出目录覆盖（obsidian.effectiveVaultDir 只读环境变量，不写共享 settings 表）。
