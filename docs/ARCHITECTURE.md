# docs/ARCHITECTURE.md — 实现架构与可靠性

> 架构决策变更先修改本文并登记 `docs/DECISIONS.md`，再动代码。

## 1. 技术栈

- Electron + React + TypeScript + Vite + Tailwind CSS
- 数据：SQLite（`node:sqlite` 内置模块，选型依据见 `DECISIONS.md` D-015）；校验：Zod
- 测试：Vitest（单元/集成）+ Playwright（端到端）；打包：electron-builder
- 运行时：优先使用本机已验证的 Node.js 24.15.0（见 `docs/REFERENCES.md` R-4）
- 依赖策略：锁定实际验证过的版本（提交 lockfile）；Electron 原生模块（better-sqlite3）与打包产物必须在真实环境验证，不得只凭文档假设。

## 2. 进程模型与安全边界

- 主进程：数据库、模型调用、提醒、文件导出。
- 渲染进程：仅 UI；通过预加载脚本暴露的**限定 IPC 白名单**调用主进程。
- 开启上下文隔离（`contextIsolation: true`），关闭渲染进程 Node 集成（`nodeIntegration: false`）。
- 不向渲染进程开放任意命令执行或任意文件读写接口；文件写入限定在专用导出目录，写入前校验路径。

## 3. 持久化对象（SQLite 至少包含）

设置、会话消息、来源快照、原则卡、日报修订、实验、报告、模型请求、用量、导出任务、提醒记录。

## 4. BigModel 接入

配置权威来源为 `docs/DECISIONS.md` D-001，要点：

- 默认 Base URL `https://open.bigmodel.cn/api/paas/v4/`；对话接口 `…/chat/completions`；默认模型 `glm-5.3-flash`。多模型兼容：设置页可改接口地址（Base URL）与模型名，适配任何 OpenAI 兼容接口（DeepSeek、Moonshot、OpenAI、本地 Ollama 等），空值回落默认。
- 鉴权 `Authorization: Bearer <API_KEY>`；Key 经 Electron `safeStorage` 加密保存，由用户在设置中输入。
- 聊天输出使用流式；提炼输出使用 JSON 结构化并本地校验。
- "测试连接"使用最小文本请求，明确报告鉴权失败、余额不足、模型不可用、限流或超时；不自动切换模型或计费接口。
- 默认请求超时 120 秒，可取消。

## 5. 模型调用纪律

1. 用户消息先落库，再发送请求；
2. 单次输入正文序列化后不超过 24KiB；输出上限 8192 tokens；
3. 长资料切片、按相关历史检索组装上下文；周期报告采用 map-reduce 分批（逐批 ≤24KiB-4KB 独立请求生成中间摘要，末次汇总各批摘要），单次请求绝不超限；
4. 不发送关闭思考的参数，遵循当前模型能力；
5. 完整响应先保存，再做结构、证据与来源校验；
6. 格式修复最多一次并计入预算；仍失败则保留草稿待用户处理；
7. 请求状态区分：未发送 / 请求中 / 结果不明 / 已验证 / 失败；
8. 提交后超时不自动重复请求；重试必须由用户明确触发；
9. 收束未成功时不标记正式日报已生成。

## 6. 预算控制

- 调用前保守预占，返回 usage 后按实际结算；结果未知时保留预占。
- 重试、格式修复与后台报告共用同一预算。
- 超出月度限额（默认 20 元，可修改）暂停所有模型调用；本地记录功能不受影响。
- 价格记录保存核查日期；不宣称能约束用户账户中其他应用的费用。

## 7. 文件与版本（Obsidian 导出）

- SQLite 是应用记录的事实来源；Obsidian 是单向导出目标。
- 首次创建笔记；修订另存新文件，不覆盖已有笔记。
- 写入使用同目录临时文件 + 原子替换，不覆盖已发布内容，写后回读核验。
- 导出任务有稳定 ID 与内容 hash；重启后重试先检查已有结果，避免重复。
- 导出失败只重试导出，不重新调用模型。
- 用户对 Obsidian 的手工修改不自动回流应用；界面明确说明该行为。
- 写入限定在专用目录并校验路径与链接跳转；不支持必要文件操作时明确失败并提供"另存为"，不假报成功。

## 8. 报告修订链

- 每份报告绑定：日报修订版本、来源、模型与提示词版本。
- 日报修改后，受影响的旧报告标记为过时；重新生成新版本并保留旧版本。

## 9. 提醒与后台

- 默认提醒窗口 21:30—23:00，可设置。
- 关闭窗口进入托盘；首次进入托盘向用户解释；显式退出才停止后台。
- 应用启动与系统睡眠恢复后，依据持久记录去重；不补发历史提醒，不唤醒已关机的电脑。
- 发出通知尝试不等于用户已看到，不得据此认为提醒成功。
- 后台报告任务串行执行；正在进行的复盘优先。

## 10. 可靠性场景与对策

| 场景 | 对策 |
|---|---|
| 超时 / 断网 | 输入已落库不丢失；状态记为失败或结果不明；不自动重发 |
| 鉴权失败 / 余额不足 | 测试连接明确报因；不切换模型或接口 |
| JSON 截断 / 格式错误 | 保留草稿；最多一次修复；不假报提炼成功 |
| 重复结束 / 崩溃 / 导出重试 | 幂等键 + 内容 hash 去重，不产生重复结果 |
| 睡眠恢复 / 重启 | 依据持久记录去重提醒，不补发、不唤醒关机电脑 |
| Obsidian 人工编辑 | 保留不覆盖；应用不回流，报告修订关系明确 |
