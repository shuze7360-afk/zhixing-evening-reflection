# docs/ACCEPTANCE.md — 验收标准

> 验收规则变更先修改本文。自检、独立审阅、真实 API 验证、安装包运行、用户试用分别记录，不得互相冒充。

## 1. ER-000 冷恢复验收协议

给独立新会话**仅提供项目路径**（不提供聊天摘要），要求它：

1. 按 `AGENTS.md` 恢复顺序读取文件；
2. 准确回答：项目目标、范围、角色、活动任务、已验证内容、下一条命令；
3. 运行 `npm run handoff:check` 且全部通过。

**反例验证**（在隔离材料副本上进行，交接检查必须失败并报出原因）：

| 反例 | 预期 |
|---|---|
| 任务指针不一致（active_task 指向不存在的任务） | 检查 04 失败 |
| 候选内容变化（改动候选范围内文件后不重新冻结） | 检查 08 失败 |
| 证据缺失（删除已自查任务的 evidence/） | 检查 06 失败 |
| 历史审阅冒充当前通过（阶段置为 reviewed 但未绑定当前候选哈希） | 检查 09 失败 |
| 生成文件与状态源失同步（改状态源后不重新渲染） | 检查 10 失败 |

框架通过冷恢复验收后，状态切换到 ER-001，交给 ZCode 开发。

## 3. 应用对抗验收（必须覆盖）

- 修耳机省钱、科研低效、休息和人际关系不会被武断判定为低价值；
- "也许可以"不会变成已接受行动；
- 编造引文和材料中的越权指令不能通过；
- 超时、断网、鉴权失败、截断 JSON：不丢输入、不假报完成；
- 重复结束、崩溃与导出重试不产生重复结果；
- Obsidian 人工编辑保留，报告修订关系正确；
- 睡眠恢复、重启和通知拦截不导致重复催促；
- 长材料和多个报告共用预算，超限停止调用；
- 无记录或少量记录时，不编造趋势。

## 4. 环境与显示矩阵

在 1366×768、1920×1080、125% 缩放及深浅主题下检查界面、长文本、空状态和失败提示。

标准见 `docs/PRODUCT.md` 第 8 节：至少五次短复盘、一个实验获得可解释反馈，并观察判断清晰度和负担。**不得据此宣称习惯已经养成。**
